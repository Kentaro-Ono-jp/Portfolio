# PR #104 correction occurrences

### Occurrence 1

- **PR:** PR #104
- **Mistake:** GitHub Actions overrode only the local S3 endpoints, leaving the API and ML settings with partial local storage configuration that the new fail-closed validation correctly rejected during static tests.
- **Correction:** Declare the complete bounded MinIO endpoint and synthetic access-key fixture for both API and ML in the workflow, isolate default/AWS-mode settings tests from workflow overrides, and assert that the workflow keeps all four credential variables aligned with the local fixture.

### Occurrence 2

- **PR:** PR #104
- **Mistake:** The container measurement command accepted repository-relative configuration and output paths but later compared the unresolved relative configuration path directly with the absolute repository root, so the completed Linux runtime proof failed while assembling evidence.
- **Correction:** Resolve measurement input and output paths from the repository root, reject paths that escape it, use the resolved paths throughout evidence assembly, and directly test both repository-relative resolution and escape rejection.

### Occurrence 3

- **PR:** PR #104
- **Mistake:** The RabbitMQ 4.2 compatibility step's runtime-only expected-version override leaked into nested unit tests of the verifier, causing mocked partial runtime tests to perform an unintended real Docker version query before the compatibility runtime started.
- **Correction:** Remove the runtime-only version override at the start of every verifier unit test while retaining the focused exact-version and mismatch tests that explicitly set their own value.

### Occurrence 4

- **PR:** PR #104
- **Mistake:** The successful container-sizing artifact used the pull-request merge checkout SHA as `sourceSha` when cold-full planning emitted no endpoint head, even though the workflow run and reviewed candidate were bound to the exact PR head.
- **Correction:** Bind measurement source identity directly to the pull-request event's exact head SHA, retain `github.sha` only for push and dispatch events, and assert that workflow expression in the executable verifier tests.
