# PR #115 implementation corrections

### Occurrence 1

- **PR:** PR #115
- **Mistake:** Image publication retried CodeBuild without first reconciling immutable exact-source ECR tags left by an interruption after the build effect and before its remote checkpoint.
- **Correction:** Inspect all three exact tags before build, reuse only a complete valid digest set, reject partial sets, and compare fresh CodeBuild exports with ECR read-back before checkpointing.

### Occurrence 2

- **PR:** PR #115
- **Mistake:** Fallback registration could create a schedule and then lose its local checkpoint, leaving retry unable to adopt the existing same-name schedule.
- **Correction:** Persist the exact fallback intent before creation, attest the controller binding, and reconcile or adopt only an exact active schedule before recording the final checkpoint.

### Occurrence 3

- **PR:** PR #115
- **Mistake:** The exact-endpoint planner used copy and rename source identities both for conservative test selection and for the changed-file count, inflating the canonical inventory.
- **Correction:** Separate destination-focused change records from source-plus-destination selection identities and add copy and rename regression coverage.

### Occurrence 4

- **PR:** PR #115
- **Mistake:** The local classic-to-quorum RabbitMQ queue change had no bounded upgrade route for the project-scoped persistent broker volume.
- **Correction:** Add an explicit standalone verifier command that stops only this Compose project and removes only its synthetic RabbitMQ volume while preserving PostgreSQL, MinIO, and unrelated Docker resources.

### Occurrence 5

- **PR:** PR #115
- **Mistake:** Fallback status trusted schedule existence instead of the complete active binding, while extension overwrote a disabled or drifted schedule before validating its live precondition.
- **Correction:** Reuse the exact schedule verifier for status and before mutation, report drift without writes, and checkpoint extension intent so an exact completed update is adopted after interruption.

### Occurrence 6

- **PR:** PR #115
- **Mistake:** Migration started an ECS task without a durable intent or idempotency token, so interruption after accepted RunTask and before checkpoint let retry launch a second database migration.
- **Correction:** Persist a lifecycle-specific migration intent first, use an exact ECS client token and task identity, checkpoint the returned task before waiting, and adopt only the exact task on retry.

### Occurrence 7

- **PR:** PR #115
- **Mistake:** An external Playwright smoke failure escaped before the lifecycle recorded that smoke had started or failed, leaving sanitized status at not-attempted.
- **Correction:** Write the running checkpoint before Playwright, record the ordinary process or evidence failure remotely, and rethrow only after the failed checkpoint is attempted.

### Occurrence 8

- **PR:** PR #115
- **Mistake:** A secondary remote checkpoint failure could replace the original migration-observation or authenticated-smoke failure as the surfaced causal error.
- **Correction:** Keep the original operation exception as the top-level failure and chain the later checkpoint error with a sanitized note.

### Occurrence 9

- **PR:** PR #115
- **Mistake:** The first complete-invariant tests sampled only three schedule drift fields even though status and extension consume a larger exact Scheduler payload.
- **Correction:** Execute both production commands against canonical, missing, expired, and one-field mutations for every schedule, target, retry, and forbidden-boundary field.

### Occurrence 10

- **PR:** PR #115
- **Mistake:** The lifecycle-wide source lease and final configuration ETag did not stop two same-source seed invocations from interleaving Cognito and credential-capsule effects before either invocation owned the operation.
- **Correction:** Conditionally checkpoint a random seed-operation owner before the first external effect, retain its exact checkout-private recovery identity across interruption, reject stale, foreign, or locally concurrent owners before mutation, and prove final Cognito/capsule/checkpoint consistency with a two-command regression.
