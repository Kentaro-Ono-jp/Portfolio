# PR #107 implementation corrections

<!-- ips-data: implementation-correction-occurrences -->

### Occurrence 1

- **PR:** PR #107
- **Mistake:** The AWS policy-matrix parser compared the integer schema version by value only, so Python accepted JSON `true` as schema version `1`.
- **Correction:** Require the exact parsed `int` type before version equality and exercise canonicalized `true` and `false` mutations through the production parser on every AWS static verification.

### Occurrence 2

- **PR:** PR #107
- **Mistake:** The generated Permissions Boundary and IAM-manager inline policy were structurally valid but exceeded AWS IAM policy-size quotas, while the mock-provider proof never checked their rendered lengths.
- **Correction:** Compact the generated authority without weakening the required ceilings, add Terraform quota preconditions, and record exact managed, inline, and trust policy sizes in the AWS-free verifier.

### Occurrence 3

- **PR:** PR #107
- **Mistake:** Destroy authority named API Gateway, Cognito, and Cloud Map wildcard resources without requiring ownership tags, so unrelated resource IDs in the account could satisfy the effective identity and boundary policies.
- **Correction:** Require matching environment, managed, and nonpersistent resource tags in both identity and boundary policies, with paired owned and cross-environment negatives for REST APIs, user pools, namespaces, and services.

### Occurrence 4

- **PR:** PR #107
- **Mistake:** The IAM manager could replace environment-role inline policies, while the boundary's `iam:PassRole` ceiling did not independently enforce same-environment targets and exact destination services against a delegated broader identity policy.
- **Correction:** Make inline policies persistent-bootstrap-owned, remove every delegated policy-mutation action, bind boundary pass-role grants to same-environment purpose targets and exact services, and exhaustively exercise the boundary against an adversarial wildcard identity policy.

### Occurrence 5

- **PR:** PR #107
- **Mistake:** The documented GitHub event allowlist was metadata only because the OIDC trust document did not connect `workflow_dispatch` or `schedule` to any enforceable condition.
- **Correction:** Require a repository-customized OIDC subject containing `event_name`, match only the complete manual and scheduled subjects in AWS trust, and deny an otherwise exact push subject in the trust matrix.

### Occurrence 6

- **PR:** PR #107
- **Mistake:** The AWS-free verifier checked trust documents against 4,096 characters while Terraform enforced the portable 2,048-character default, and its new policy-structure guards were exercised only by a passing payload.
- **Correction:** Align both boundaries at 2,048 characters and run canonicalized over-quota, delegated-policy-mutation, and disconnected-event mutations through the production structure verifier before publishing evidence.
