# PR #107 implementation corrections

<!-- ips-data: implementation-correction-occurrences -->

### Occurrence 1

- **PR:** PR #107
- **Mistake:** The AWS policy-matrix parser compared the integer schema version by value only, so Python accepted JSON `true` as schema version `1`.
- **Correction:** Require the exact parsed `int` type before version equality and exercise canonicalized `true` and `false` mutations through the production parser on every AWS static verification.

### Occurrence 2

- **PR:** PR #107
- **Mistake:** The generated Permissions Boundary and IAM-manager inline policy were structurally valid but exceeded AWS IAM policy-size quotas, while the mock-provider proof never checked their rendered lengths.
- **Correction:** Compact the generated authority without weakening the required ceilings, add Terraform quota preconditions, and record exact managed, inline, and trust policy sizes in the AWS-free verifier.

### Occurrence 3

- **PR:** PR #107
- **Mistake:** Destroy authority named API Gateway, Cognito, and Cloud Map wildcard resources without requiring ownership tags, so unrelated resource IDs in the account could satisfy the effective identity and boundary policies.
- **Correction:** Require matching environment, managed, and nonpersistent resource tags in both identity and boundary policies, with paired owned and cross-environment negatives for REST APIs, user pools, namespaces, and services.

### Occurrence 4

- **PR:** PR #107
- **Mistake:** The IAM manager could replace environment-role inline policies, while the boundary's `iam:PassRole` ceiling did not independently enforce same-environment targets and exact destination services against a delegated broader identity policy.
- **Correction:** Make inline policies persistent-bootstrap-owned, remove every delegated policy-mutation action, bind boundary pass-role grants to same-environment purpose targets and exact services, and exhaustively exercise the boundary against an adversarial wildcard identity policy.

### Occurrence 5

- **PR:** PR #107
- **Mistake:** The documented GitHub event allowlist was metadata only because the OIDC trust document did not connect `workflow_dispatch` or `schedule` to any enforceable condition.
- **Correction:** Require a repository-customized OIDC subject containing `event_name`, match only the complete manual and scheduled subjects in AWS trust, and deny an otherwise exact push subject in the trust matrix.

### Occurrence 6

- **PR:** PR #107
- **Mistake:** The AWS-free verifier checked trust documents against 4,096 characters while Terraform enforced the portable 2,048-character default, and its new policy-structure guards were exercised only by a passing payload.
- **Correction:** Align both boundaries at 2,048 characters and run canonicalized over-quota, delegated-policy-mutation, and disconnected-event mutations through the production structure verifier before publishing evidence.

### Occurrence 7

- **PR:** PR #107
- **Mistake:** The operator's EC2 inventory and existing-resource mutation actions shared creation-time request-tag conditions, so real requests without synthetic creation tags were denied.
- **Correction:** Separate request-tagged creation, unconditioned inventory, and resource-tagged mutation statements, then exercise each real action context independently through identity, boundary, and effective policy layers.

### Occurrence 8

- **PR:** PR #107
- **Mistake:** The operator omitted the HTTP API collection create ARN, resource-less Cognito and Cloud Map create grants, and required tagging actions, leaving ownership-tagged control-plane resources uncreatable.
- **Correction:** Add only the actual create-time resource forms and tagging actions with the complete repository ownership tuple and an exact tag-key allowlist, require existing ownership before Cognito retagging, and retain positive, unowned, and cross-environment policy cases.

### Occurrence 9

- **PR:** PR #107
- **Mistake:** The boundary used a `*-workload` PassRole resource and the adversarial verifier enumerated only declared targets, so an undeclared same-environment workload ARN could be passed to ECS.
- **Correction:** Replace the wildcard with the four exact ECS role ARNs, reject every boundary PassRole wildcard structurally, and synthesize undeclared wildcard-matching, copied-purpose, global, and external targets in the exhaustive adversarial matrix.

### Occurrence 10

- **PR:** PR #107
- **Mistake:** The first tagging repair grouped Cognito `TagResource` with create-time request-tag authority, which could retag an unowned pool and accepted ownership requests without an exact tag-key ceiling.
- **Correction:** Separate create and tag statements, require the existing Cognito resource to carry the complete repository ownership tuple, restrict both Cognito and Cloud Map tag requests to the four ownership keys, and prove the unowned Cognito negative independently at identity, boundary, and effective layers.

### Occurrence 11

- **PR:** PR #107
- **Mistake:** The exact ownership-tag allowlist had passing and cross-environment cases but did not execute the evaluator branch that rejects an additional undeclared tag key.
- **Correction:** Add a canonical Cloud Map `TagResource` negative with the four required ownership keys plus one undeclared key, and require the effective policy to deny it before publication.

### Occurrence 12

- **PR:** PR #107
- **Mistake:** The EC2 positive supplied a VPC ARN and resource tags to `ModifyVpcAttribute`, although AWS exposes neither resource-level authorization nor resource-tag context for that action, so the real request was denied at every layer.
- **Correction:** Remove the unsupported `Modify*` grant and prove `AuthorizeSecurityGroupIngress` against its required existing security-group resource-tag context plus the optional new security-group-rule request-tag context, including environment, repository, and tag-key inverses.

### Occurrence 13

- **PR:** PR #107
- **Mistake:** Generated-ID destroy grants omitted repository ownership, and HTTP API creation did not require the repository tag or exact tag-key set, so same-environment resources from another repository and extra-key creates remained effective.
- **Correction:** Bind every generated-ID and network ownership tuple to repository, environment, managed, and nonpersistent tags; require exact request tag keys on HTTP API and EC2 creation; and vary repository independently in create and destroy proof.

### Occurrence 14

- **PR:** PR #107
- **Mistake:** Cloud Map `CreateService` was simulated once against `*`, hiding AWS's separate required authorization of the existing namespace and newly created service resources.
- **Correction:** Split the identity grant and proof across an ownership-tagged namespace ARN and a request-tagged service ARN, then reject a foreign namespace independently before treating service creation as usable.

### Occurrence 15

- **PR:** PR #107
- **Mistake:** Duplicating every generated-resource ownership predicate in the one fixed Permissions Boundary left only 28 characters at the maximum accepted prefix and would force quota-driven redesign whenever AWS service semantics changed.
- **Correction:** Apply the owner-selected durable-boundary rule: keep service/purpose, persistent-resource, IAM-mutation, and exact PassRole ceilings in the fixed boundary; enforce exact resource ownership in bootstrap-owned inline policies that delegated roles cannot replace; preserve source-readable statement labels without rendering quota-costly Sids; reserve 512 characters in both managed-boundary and aggregate-inline budgets; and prove each layer plus the effective intersection with truthful per-layer expectations.

### Occurrence 16

- **PR:** PR #107
- **Mistake:** Operator proof covered HTTP API collection creation but omitted the rendered `PATCH`, child `POST`, and `PUT` forms, leaving existing foreign API resources writable without ownership conditions in the identity policy and effective intersection.
- **Correction:** Keep the fixed boundary coarse, move all three existing-resource HTTP API write verbs into a bootstrap-owned ownership-tagged identity statement, and derive owned, cross-environment, and cross-repository decisions for every rendered verb/resource form.
