# PR #111 implementation corrections

<!-- ips-data: implementation-correction-occurrences -->

### Occurrence 1

- **PR:** PR #111
- **Mistake:** The environment root referenced an operator role whose identity policy and fixed permissions boundary did not effectively allow all AWS provider calls required to apply the declared resources.
- **Correction:** Replaced the unpublished Terraform IAM change with separately named Console-owned OperatorPermissions and OperatorBoundary definitions, accepted exact Console-owned role ARNs, and added a provider-version-pinned action matrix that verifies every planned operation against both policy layers.

### Occurrence 2

- **PR:** PR #111
- **Mistake:** The first live apply exposed provider-dependent tag authorization calls, an EC2 prefix-list read, and an API Gateway service-linked-role prerequisite that the initial static action matrix did not model.
- **Correction:** Added the exact tag and prefix-list actions to the Console-owned OperatorPermissions contract, recorded all four service-linked roles as owner-created prerequisites, and extended the two-layer action-matrix proof before retrying the saved environment configuration.

### Occurrence 3

- **PR:** PR #111
- **Mistake:** The second live apply proved that recovery from a partially created Security Group rule set requires `ec2:ModifySecurityGroupRules`, although a clean create-only plan does not exercise that action.
- **Correction:** Added the exact rule-modification action to OperatorPermissions and to both ingress and egress lifecycle rows in the two-layer action matrix before the final construction attempt.

### Occurrence 4

- **PR:** PR #111
- **Mistake:** The post-create real plan reached three provider refresh helpers that were absent from the pre-create matrix: Cognito client listing, MQ shared-resource description, and Secrets Manager resource-policy reading.
- **Correction:** Added only those three read actions to OperatorPermissions and their owning resource rows, and required a successful post-create plan before consuming the final construction attempt.

### Occurrence 5

- **PR:** PR #111
- **Mistake:** The MQ resource used accepted but non-canonical enum casing, so provider 6.58.0 read back `RabbitMQ`, `simple`, and `ebs` and produced a perpetual broker replacement after the first real refresh.
- **Correction:** Switched the MQ configuration and plan assertions to the provider's canonical read-back casing while preserving the RabbitMQ 4.2, EBS, and simple-authentication contract.

### Occurrence 6

- **PR:** PR #111
- **Mistake:** The third and final construction attempt exposed two delegated create dependencies absent from the matrix: API Gateway tags authorize through `apigateway:TagResource`, and Cloud Map private namespace creation invokes Route 53 hosted-zone creation under the caller.
- **Correction:** Added exact API Gateway tag rows, modeled Cloud Map's documented Route 53 create/read dependencies as service-delegated actions, and stopped further construction after the governed `3/3` attempt limit.

### Occurrence 7

- **PR:** PR #111
- **Mistake:** The first owner-authorized destroy reached provider cleanup paths that inspect and detach managed network interfaces, but the separate destroy policy omitted `ec2:DescribeNetworkInterfaces` and `ec2:DetachNetworkInterface`.
- **Correction:** Added both actions only to the Console-owned DestroyPolicy, retained the independent OperatorPermissions grant and OperatorBoundary ceiling, and extended static proof to require effective destroy cleanup authority without granting network-interface detachment to the operator role.

### Occurrence 8

- **PR:** PR #111
- **Mistake:** The destroy-authority verifier correction was pushed before the canonical Ruff formatting check, so the complete static verification stopped at API formatting despite the focused AWS proof passing.
- **Correction:** Applied canonical Ruff formatting to the verifier, retained the effective-authority assertions unchanged, and restarted publication Gate A from the corrected committed head.

### Occurrence 9

- **PR:** PR #111
- **Mistake:** The human-readable implementation record was corrected to the consumed `3/3` construction limit, but both AWS-free evidence generators still emitted the obsolete pre-evaluation `0/3` value.
- **Correction:** Updated bootstrap and environment machine evidence to report the same governed `3/3` historical attempt count, preserving zero AWS calls, writes, and resources as properties of each static verifier rather than conflating them with live history.

### Occurrence 10

- **PR:** PR #111
- **Mistake:** The first Console-owned DestroyPolicy grouped generated-ID and dependent cleanup actions under `Resource: "*"` without immutable ownership or AWS service-delegation conditions, so unrelated account resources could satisfy the destroy identity grant.
- **Correction:** Removed the undocumented Route 53 delete grant; split remaining destroy authority into complete ownership-tag, exact environment-name ARN, and AWS-supplied Amazon MQ `aws:CalledVia` statements; isolated AWS's resource-global task-definition deregistration action; and added paired cross-environment, cross-repository, unmanaged, persistent, direct-call, wrong-service, quota, and adversarial boundary proofs.

### Occurrence 11

- **PR:** PR #111
- **Mistake:** The live API Gateway `TagResource` operation was copied into the IAM policy as `apigateway:TagResource`, but API Gateway Management V2 authorizes that operation with its HTTP-method IAM actions and AWS Access Analyzer correctly rejected the invented action.
- **Correction:** Mapped the provider's tag calls to `apigateway:POST` on the API, Stage, and VPC Link resource forms, removed the invalid action, and made the AWS-free verifier reject every API Gateway IAM action outside the exact reviewed method set.
